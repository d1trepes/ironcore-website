## Правила для следующего чата / этап 02

1. В начале проверить `README.md`, этот `docs/PROJECT_STATE.md`, `docs/content.md`, `docs/tz-checklist.md`, `docs/page-blueprint.md`, `docs/visual-direction.md`, `docs/design-rules.md` и `docs/brand-identity.md`.
2. Подготовить **полную авторскую структуру всех 11 разделов** строго по ТЗ: бизнес-цель, маршрут до заявки, отличие композиции и интеракций каждого раздела, адаптив и обязательное содержание.
3. Не превращать страницу в повтор одинаковых карточек, не использовать AI-клише, не придумывать факты и не терять ТЗ. При этом сделать продукт коммерчески ясным и необычным по композиции.
4. **Сначала показать структуру целиком в чате, дождаться прочтения/одобрения дизайнера. Ничего не фиксировать в GitHub как утверждённую структуру до разрешения.** Код сайта не начинать.
5. После согласования — зафиксировать утверждённую структуру в `docs/page-blueprint.md` (либо отдельном согласованном файле), обновить этот статус, дать промпт для Claude на дизайн/сборку по спецификации.
6. Готовый промпт для следующего короткого чата лежит в `docs/next-chat-structure-prompt.md`.

## Неизменные ограничения

- Главный источник: `docs/content.md` (11 разделов) и `docs/tz-checklist.md`; полные формулировки и все цифры сохраняются.
- Первый ранее показанный hero слишком слаб, второй слишком перегружен: будущий визуал — выразительный, но легко считываемый.
- Не изобретать кейсы, партнёров, сертификаты, цифры, услуги и гарантии.
- Архивные репозитории `ironcore-landing` и `ironcore-hero` не редактировать.
- GitHub — источник актуальных решений; Claude — исполнитель кода; WordPress — следующий этап за пределами демо.

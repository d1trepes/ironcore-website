## Подбор изображений в демо (2026-11-13)
Отзыв заказчика: картинки почти одинаковые (везде сумерки, степь, графит), внешний вид — не только серый; нужны разные кадры: стойки, серверы, коридоры, инженерия.
- **Только демо (GitHub Pages).** WordPress-тема не тронута: `build-theme.sh` не копирует `demo/`, тема не использует `index.html`. В WP переносим после того, как заказчик выберет.
- Панель «Подбор изображений» (кнопка слева внизу): 23 места на странице, у каждого варианты A (текущий) + B, C (новые). Клик меняет картинку на странице, сам открывает нужную вкладку/услугу и прокручивает к месту. Выбор хранится в браузере; «Скопировать выбор списком» и «Ссылка с выбором» (`?img=hero.b,eng-cooling.c`) — чтобы заказчик прислал решение. `?pick` открывает панель, `?clean` прячет кнопку.
- Места разведены: «Инженерная инфраструктура» (услуги) и «Энергоэффективность» больше не обязаны показывать один кадр; фон полосы отделён от «Классического ЦОД».
- Промпты: `docs/image-prompts.md` (46 шт., генерируется из `demo/tools/slots.py`). Hero и «Безопасность» — только правкой текущей картинки, иначе съедут выноски и 6 точек.
- Добавление картинок: файлы `<место>-<буква>.png` → `python3 demo/tools/add.py папка/` → WebP 640/1024/полный в `demo/variants/`, пересборка `demo/variants.js`.
- Панель подбора: выезжает справа, язычок без счётчика (стрелка + подпись; на телефоне — внизу справа), синие полосы прокрутки, сброс кэша ?v=3. Для B/C первый экран закрывается картинкой целиком (cover) только на desktop (>960 px): слева мягкое постепенное размытие в 3 слоя (blur 10/5/2 px, сходит на нет к ~55% ширины) + лёгкое затемнение; выноски поверх размытия; у кнопок размытия нет. На ≤960 px — прежняя компоновка (картинка целиком под текстом, выноски на месте), фон блока подобран под цвет неба варианта (поле sky в slots.py), светлее. Смена картинки: новая сначала грузится и декодируется в фоне, старая видна до замены (без пустого экрана); предзагрузка при наведении/касании плитки; на телефоне после выбора панель закрывается и показывает место. A без изменений.
- Волны B и C (2026-11-13): готово 46 из 46 (контейнер B — с третьей попытки, строго в торец). В панели кнопки «Все B» и «Все A». По умолчанию на сайте A. hero-c и security-c — своя раскладка выносок и точек.
- У hero-b и security-b своя раскладка выносок и 6 точек (поле layout в slots.py), при выборе A возвращается исходная.

## WordPress handoff (2026-11-12)
По словам пользователя, проект готов; задача — подготовить передачу WordPress-разработчику.
- Тема `wordpress/ironcore/`, готовый архив `wordpress/dist/ironcore-theme.zip`, сборка `wordpress/build-theme.sh`. CSS/JS/ассеты — те же файлы, что у статики (единый источник).
- Разметка 10 разделов + футер перенесена из index.html 1:1. Проверено в WordPress 7.2-beta + PHP 8.3: полностраничные скриншоты статики и темы на 1440/1024/390 совпадают по высоте, отличия — перенос одной подписи над чипсами и кадр пульсации точки. JS-ошибок нет.
- Форма подключена: admin-ajax → запись «Заявки» в админке → письмо с вложениями → Telegram (если настроен). «Заявка отправлена» показывается только после сохранения. Ловушка, время заполнения, лимит 5/10 мин на IP, проверка типов файлов, файлы в закрытой папке, скачивание из карточки заявки. Проверено: валидация, отправка из #contact и из модалки, файл PDF, отказ .exe, скачивание файла из админки.
- Согласие на ПДн: обязательная галочка появляется, только когда опубликована страница политики (Настройки → Конфиденциальность). **Новый элемент формы — дизайнеру посмотреть.**
- Customizer «IronCore: контакты и заявки»: телефон, e-mail, Telegram, мессенджеры, реквизиты, title/description. Меню «Шапка» и «Футер» с утверждёнными пунктами по умолчанию. Внутренние страницы (политика, 404) — тот же header/footer, светлая колонка текста.
- Статика (GitHub Pages) не изменилась визуально: без WordPress форма остаётся в демо-режиме.
- Инструкция: docs/wordpress-handoff.md (установка, сервер, nginx-правило, что ждёт материалов заказчика, приёмка).
- Не проверено: реальная доставка почты и Telegram (на тестовом стенде нет почтового сервера и бота), nginx, хостинг заказчика. Этап 04 QA (docs/qa-report.md) отдельно не проводился; mobile v1.2 формально не отмечен утверждённым.

## Desktop v3 — правки к v2
- Шапка: меню строго по центру между логотипом и кнопкой (grid 1fr auto 1fr).
- Убраны отдельные подстрочные блоки (оговорка про абсолютную защищенность осталась только в FAQ, как в ТЗ). Сноска об иллюстративных диапазонах обязательна по CLAUDE.md, поэтому она внутри карточки масштаба под цифрами, а не отдельной строкой.
- Безопасность: карточки рисков и точки на разрезе закрываются повторным кликом.
- Масштабы и инженерия: новый переключатель на всю ширину (название + ключевые цифры/подпись, активная линия сверху).
- «Форматы размещения» — заголовок того же уровня и начертания, что H2, с подзаголовком.
- Услуги: только по клику, без наведения; плюс/крестик показывает состояние.
- Типографика: тире и короткие слова не переносятся отдельно (неразрывные пробелы), text-wrap balance/pretty.
- Процесс: заголовок и кнопка закреплены слева, справа 6 строк «этап — результат»; этапы подсвечиваются по мере чтения (привязка к скроллу, без быстрой анимации).
- Резервирование: три колонки N / N+1 / 2N с наглядными модулями и легендой.
- Финальный блок «Начинаем с требований…» — фото-полоса с тремя строками лесенкой и кнопкой.
- Контакты: форма на тёмном фоне без белой плашки; 5 исходных данных из раздела 06 стали кнопками-подсказками, которые добавляют строку в комментарий; телефон отдельным блоком «Удобнее голосом».
- Футер: три колонки с подписями «Разделы» и «Связаться», ссылки в две колонки без переносов.
- Скорость: для всех изображений версии 640/1024 px + srcset/sizes (экономия ~60–80% на 1440), изображения во вкладках подгружаются заранее при подходе к разделу.

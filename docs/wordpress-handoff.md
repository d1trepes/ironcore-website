# IRONCORE — передача сайта WordPress-разработчику

## Что должен передать дизайн-этап
- Репозиторий с HTML/CSS/JS демоверсией всех 11 разделов.
- Выбранные SVG-логотипы, favicon, полноразмерные и оптимизированные изображения.
- Тексты и цифры из `docs/content.md`, карта разделов `docs/page-blueprint.md`.
- Адаптивные состояния (desktop/tablet/mobile), состояния меню, вкладок, модалок, ошибок формы, FAQ и hover/focus.
- README запуска демо без внешних секретов, список зависимостей и точное описание возможностей, которые пока заглушки.

## Задачи WordPress-разработчика (не считать готовыми на этапе дизайна)
- Перенести разметку и стили в тему/шаблоны и определить редактируемые области.
- Реализовать серверную обработку формы, хранение вложений и уведомления в Telegram-бот/CRM; защита от спама, валидация, ограничения файлов, безопасная обработка ПДн.
- Установить политику обработки данных, согласие, юридические реквизиты и настоящие контакты.
- Добавить предоставленные PDF и действующие ссылки на скачивание.
- Проверить SEO-метаданные, sitemap, производительность, семантику и доступность на боевом сервере.
- Настроить домен/SSL/аналитику/безопасность по отдельному согласованию.

## Демоверсия — что считаем «готовым»
- Полная страница и адаптив, работающие локальные интерфейсные взаимодействия и осмысленные изображения.
- Форма демонстрирует интерфейс **без отправки заявок** (написать это явно); не показывать ложное сообщение об отправке.
- Отсутствующие PDF и внешние ссылки помечены как ожидающие материалов. Нет 404 при демонстрации.
- README объясняет, что WordPress и реальные интеграции будут выполнены отдельно.

## Репозиторий для WordPress
Второй репозиторий не обязателен. Разработчик может получить текущий `d1trepes/ironcore-website` в режиме чтения, клонировать его/форкнуть или вести собственный репозиторий для WordPress. Не передавать лишний доступ без необходимости.

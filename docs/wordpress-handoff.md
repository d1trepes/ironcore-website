# IRONCORE — передача сайта WordPress-разработчику

Обновлено: 2026-11-12. Тема собрана из утверждённой HTML-версии (`index.html`, `css/`, `js/`, `assets/`) и проверена в реальном WordPress.

## 1. Что передаётся

| Что | Где |
|---|---|
| Готовая тема (zip для загрузки в админку) | `wordpress/dist/ironcore-theme.zip` |
| Исходники темы (PHP) | `wordpress/ironcore/` |
| Сборка zip из исходников | `wordpress/build-theme.sh` |
| Статическая версия (эталон вида и поведения) | `index.html` + `css/styles.css` + `js/main.js` |
| Изображения: оригиналы WebP + версии 640w/1024w | `assets/images/` (карта — `docs/assets-manifest.md`) |
| Логотипы SVG (основной с красным кубом) | `assets/logos/current/` |
| Шрифт Onest, self-hosted, SIL OFL 1.1 | `assets/fonts/` (+ `OFL-LICENSE.txt`) |
| Тексты и цифры ТЗ | `docs/content.md`; структура — `docs/page-blueprint.md` |

CSS и JS у статики и темы **одни и те же файлы**: правки вносятся в `css/styles.css` и `js/main.js` в корне, затем `./wordpress/build-theme.sh`. Скрипт копирует их в тему (путь к шрифтам меняется на `../fonts/`) и собирает zip. Копировать руками не нужно.

## 2. Установка (≈10 минут)

1. WordPress 6.3+ (проверено на 7.2), PHP 7.4+ (проверено на 8.3), расширения `mbstring`, `fileinfo`.
2. Внешний вид → Темы → Добавить → Загрузить тему → `ironcore-theme.zip` → Активировать.
3. Настройки → Чтение: «Ваши последние записи» или любая статическая страница — главная всё равно рисуется шаблоном `front-page.php`.
4. Настройки → Постоянные ссылки: «Название записи» (для страницы политики).
5. Внешний вид → Настроить → **«IronCore: контакты и заявки»**: телефон, e-mail для заявок, Telegram, реквизиты (см. п. 4).
6. Настройки → Конфиденциальность: создать и опубликовать страницу политики ПДн. Как только она есть, в форме появляется обязательная галочка согласия со ссылкой, а в футере — ссылка на политику.
7. Отправить тестовую заявку с главной и из модалки; проверить письмо, Telegram и раздел «Заявки».

Сразу после активации сайт выглядит как утверждённый макет: меню, телефон и подписи имеют значения по умолчанию.

## 3. Устройство темы

```
ironcore/
  style.css              заголовок темы
  functions.php          подключает inc/*
  inc/helpers.php        телефон, якоря, меню, мессенджеры
  inc/setup.php          поддержка темы, меню, CSS/JS, preload, title/description
  inc/customizer.php     настройки «IronCore: контакты и заявки»
  inc/form.php           приём заявок, тип записи «Заявки», письмо, Telegram, файлы
  header.php             шапка + мобильное меню
  front-page.php         главная: 10 разделов по порядку
  template-parts/sections/01-hero.php … 10-contact.php
  footer.php             раздел 11 (футер), модалка, шаблон формы
  page.php, index.php, 404.php + theme-assets/page.css   внутренние страницы
  assets/                css, js, fonts, images, logos (кладёт build-theme.sh)
  screenshot.jpg
```

- Разметка разделов перенесена из `index.html` без изменений; пути к картинкам идут через константу `IC_ASSETS`. Сравнение полностраничных скриншотов статики и WordPress на 1440, 1024 и 390 px: одинаковая высота страницы, отличия только в переносе строки одной подписи над чипсами формы и кадре пульсации точки на разрезе.
- На главной отключены стили блочного редактора (`wp-block-library`, `global-styles`, `classic-theme-styles`), чтобы они не сдвигали вёрстку. jQuery не используется.
- Скрипт `main.js` один на статику и WordPress: если тема вывела `window.IRONCORE`, форма шлёт заявки на сервер, иначе остаётся честный демо-режим.

### Тексты
Тексты лежат прямо в `template-parts/sections/*.php` — так вёрстка гарантированно совпадает с утверждённой. Если заказчик хочет править тексты из админки, рекомендуемый путь — ACF (поля на странице «Главная») с подстановкой значений в те же шаблоны; список полей удобно взять по разделам из `docs/content.md`. Это отдельная задача, в текущую тему не входит.

### Меню
Две области: «Шапка и мобильное меню» и «Футер, колонка Разделы». Если меню не назначено, выводятся утверждённые пункты. Пункты-якоря вводить как «Произвольная ссылка» вида `#solutions`; на внутренних страницах тема сама превращает их в `/#solutions`. Вложенные пункты не выводятся (в дизайне их нет).

Якоря разделов: `#hero #security #solutions #services #process #engineering #why #materials #faq #contact`.

## 4. Настройки «IronCore: контакты и заявки»

| Поле | Что делает |
|---|---|
| Телефон | Шапка-меню, контакты, футер, сообщения формы. `tel:` строится сам (8 → +7). |
| E-mail для заявок | Куда уходит письмо. Пусто — адрес администратора. |
| Telegram chat_id / токен бота | Дублирование заявок в Telegram. Токен лучше задать в `wp-config.php`: `define( 'IRONCORE_TG_TOKEN', '…' );` (можно и `IRONCORE_TG_CHAT`). |
| Ссылки Telegram / MAX | Появляются в нижней строке футера. Пусто — не выводятся. |
| Реквизиты | Нижняя строка футера. Пока реквизитов, мессенджеров и политики нет, там стоит утверждённая пометка «Реквизиты компании и мессенджеры будут добавлены». |
| Title / description главной | Только если не стоит SEO-плагин (Yoast, Rank Math, AIOSEO, SEOPress — тогда тема их не выводит). |

## 5. Форма заявок

Одна форма (шаблон в `footer.php`) монтируется в `#contact` и в модалку. Все неякорные кнопки сайта открывают модалку; её заголовок и поле «Откуда» берутся из текста кнопки, поэтому в заявке видно, с какой кнопки она пришла.

Поля: имя*, телефон* (≥10 цифр), комментарий, чипсы-подсказки (дописывают строку в комментарий), до 5 файлов по 10 МБ (PDF, DOC/DOCX, XLS/XLSX, ODT, ODS, JPG, PNG, ZIP; чертежи DWG — в ZIP), согласие на ПДн (только при опубликованной политике).

Путь заявки: `admin-ajax.php?action=ironcore_lead` → проверки → запись типа «Заявки» (статус «Личное», видят редакторы и администраторы) → письмо с вложениями (до 20 МБ суммарно) → сообщение в Telegram (без файлов, со ссылкой на заявку в админке). Посетитель видит «Заявка отправлена» только после сохранения в базе. Колонка «Доставка» в списке заявок показывает, ушли ли письмо и Telegram.

Защита: скрытое поле-ловушка, минимальное время заполнения, не больше 5 заявок с одного IP за 10 минут, проверка типа файла по содержимому, случайные имена файлов. Nonce проверяется только для вошедших пользователей — у гостей страница обычно отдаётся из кэша, и устаревший nonce блокировал бы реальные заявки.

Файлы лежат в `wp-content/uploads/ironcore-leads/`, скачиваются из карточки заявки через WordPress (проверка прав). При удалении заявки удаляются и её файлы.

Хук для CRM: `do_action( 'ironcore_lead_saved', $post_id, $lead, $delivery )`. Типы файлов меняются фильтром `ironcore_form_mimes`, лимиты — константами `IC_FORM_MAX_FILES`, `IC_FORM_MAX_MB`, `IC_FORM_RATE` в `wp-config.php`.

## 6. Что обязательно сделать на сервере

1. **Почта.** Стандартный `wp_mail()` на многих хостингах не доходит. Поставить WP Mail SMTP (или аналог) с ящиком домена и отправить тест.
2. **Закрыть папку заявок.** Для Apache тема кладёт `.htaccess` сама. Для **nginx** добавить в конфиг сайта:
   ```nginx
   location ^~ /wp-content/uploads/ironcore-leads/ { deny all; return 404; }
   ```
   Проверка: прямая ссылка на файл из этой папки должна давать 403/404.
3. **Лимиты загрузки:** `upload_max_filesize ≥ 10M`, `post_max_size ≥ 55M` (5 файлов + поля). Иначе уменьшить `IC_FORM_MAX_*`.
4. **Кэш страниц.** Можно кэшировать главную целиком; `admin-ajax.php` не кэшировать (плагины кэша его и так пропускают).
5. HTTPS, резервные копии БД и `uploads/`, обновления ядра.
6. После переноса на домен проверить, что картинки и шрифты грузятся с нового адреса (пути строятся от темы, абсолютных ссылок в коде нет).

## 7. Что не входит в тему и ждёт материалов заказчика

- Текст политики обработки ПДн и реквизиты компании — юридический текст даёт заказчик. Требования 152-ФЗ к согласию проверить с юристом.
- Реальные PDF для раздела 08 («Пример концепции», «Состав проектных материалов», «Чек-лист исходных данных»). Сейчас кнопки «Запросить…» честно открывают форму. Когда файлы появятся — загрузить в медиатеку и заменить кнопки в `08-materials.php` на ссылки.
- Ссылки Telegram/MAX, токен и чат бота, e-mail для заявок.
- Интеграция с CRM (через хук `ironcore_lead_saved`).
- Аналитика (Яндекс Метрика и т. п.) и согласие на cookie, если это нужно заказчику.
- SEO: плагин, OG-картинка, sitemap (ядро WordPress уже отдаёт `/wp-sitemap.xml`).
- Hero в большем разрешении (≥2560 px) — желательно для Retina; отдельный вертикальный кадр hero для телефонов (сейчас общий рендер).

## 8. Интерактивные состояния (сверять с `index.html`)

Шапка: прозрачная на первом экране, плотная после 24 px прокрутки, прячется при прокрутке вниз и возвращается при прокрутке вверх. Активный пункт меню подсвечивается по разделу. Мобильное меню ≤960 px: панель справа, Esc/затемнение/крестик закрывают, фокус заперт внутри.
Hero: выноски, лёгкий параллакс (только desktop). Безопасность: 6 точек на разрезе и список синхронизированы, повторный клик закрывает. Масштабы и инженерия: вкладки (стрелки, Home/End). Услуги: аккордеон с переключением фото. Процесс: этапы подсвечиваются по прокрутке. FAQ: `<details>`. Модалка: `<dialog>`, Esc, клик по фону, возврат фокуса. Все эффекты отключаются при `prefers-reduced-motion`.
Брейкпоинты: 1440 / 1024 / ≤960 / ≤600 / ≤380 px.

## 9. Приёмка после выкладки

- [ ] Главная совпадает со статической версией на 1440, 1024, 768, 390, 360 px, нет горизонтальной прокрутки.
- [ ] Все пункты меню и кнопки ведут куда нужно; модалка открывается со всех неякорных кнопок.
- [ ] Заявка из `#contact` и из модалки приходит на почту и в Telegram, видна в «Заявках», файл скачивается из карточки.
- [ ] Прямая ссылка на файл в `uploads/ironcore-leads/` закрыта.
- [ ] Политика опубликована, галочка согласия обязательна, ссылки в форме и футере работают.
- [ ] Телефон, реквизиты, мессенджеры — реальные.
- [ ] Консоль браузера без ошибок; Lighthouse без критичных замечаний.
